## 三、技术栈详情

| 层级 | 技术选型 | 理由 |
|------|----------|------|
| **后端框架** | Cloudflare Workers | Edge 计算，冷启动快，无需服务器管理 |
| **语言** | TypeScript | 全栈统一类型，编译期检查 |
| **LLM** | Claude API (Sonnet 4) | 高精度，医疗场景需要可靠推理 |
| **Agent 框架** | 自定义编排器 | 轻量，规则引擎优先，不需要 LangChain |
| **数据库** | Cloudflare D1 (SQLite) | 关系数据存储 |
| **缓存** | Cloudflare KV | 评估结果高速读写 |
| **前端** | React + TailwindCSS | 轻量组件化，自定义设计 |
| **构建** | Vite + tsx | 快速开发迭代 |

## 四、核心数据流

```
用户输入: "恶心想吐已经2天了，吃不下东西"
    │
    ▼
Symptom Parser（规则 + LLM）
    │  识别: 恶心呕吐(0.9), 食欲下降(0.7)
    │  持续: 2天
    ▼
Risk Assessor（规则 + RAG + LLM）
    │  Layer 1: MR-002 恶心呕吐影响进食(2天) → medium
    │  Layer 2: CTCAE 恶心呕吐管理指南
    │  Layer 3: LLM 综合 → medium (置信度 0.85)
    ▼
Advice Generator
    │  即时行动: 联系团队调整止吐方案
    │  警告信号: 呕吐带血、无法进水、高烧
    ▼
最终响应
    risk_level: "medium"
    risk_score: 65
    triggered_rules: ["MR-002"]
    immediate_action: "建议您今天联系您的医疗团队"
```

## 五、三层决策架构详解

### Layer 1: 规则引擎

**职责**：高置信度已知危险症状的快速识别

**特点**：
- 基于关键词正则匹配，速度极快（<5ms）
- 高风险规则：直接返回，不需要 LLM（安全优先）
- 原始文本优先匹配（比症状列表更直接）

**规则数量**：
- 高风险（HR）：6 条
- 中风险（MR）：6 条
- 组合升级规则：4 条

**示例**：
```
输入: "突然感觉胸闷，呼吸困难"
→ 原始文本命中 HR-001 → 高风险 → 直接返回
```

### Layer 2: RAG 检索

**职责**：提供循证医学上下文

**知识库**：
- CTCAE v5.0：194 条不良事件术语
- 副作用管理指南：17 条详细条目
- 临床试验数据：170 项

**触发条件**：规则引擎未命中高风险

### Layer 3: Claude LLM

**职责**：处理复杂/模糊输入，综合上下文做最终判断

**使用场景**：
- 症状描述模糊（如"感觉不太舒服"）
- 多个低风险症状组合
- 需要个性化建议时

**降级策略**：无 API Key 时完全跳过，纯用规则引擎

## 六、关键设计决策

### 决策 1：规则优先，LLM 作为补充

**原因**：
- 医疗场景要求响应速度（<500ms）
- 高风险症状必须第一时间识别
- LLM 成本和延迟较高

**效果**：高风险场景 <10ms 响应，无 LLM 调用

### 决策 2：TypeScript + Cloudflare Workers

**原因**：
- 部署简单，无服务器管理
- TypeScript 编译期类型检查
- 边缘计算，低延迟

### 决策 3：本地知识库 RAG（非向量检索）

**原因**：
- 当前症状-规则映射足够简单（关键词匹配）
- 向量检索增加复杂度和成本
- 知识库规模小（<200 条），无需向量检索
