# 乳腺癌患者副作用管理系统 (SABA) — 产品需求文档 v2.0

> **SABA**: Side-Effect Assessment for Breast cancer patients with AI-powered feedback

---

## 一、问题陈述与愿景

### 1.1 当前痛点

乳腺癌患者在治疗期间（手术/化疗/靶向/内分泌治疗）会经历多种副作用。现有问题：

| 痛点 | 影响 |
|------|------|
| 副作用报告滞后 | 患者往往在下次门诊才告知，延误干预时机 |
| 医患信息不对称 | 患者难以判断症状严重性，容易过度焦虑或低估风险 |
| 缺乏实时支持 | 非工作时间无法获得专业指导 |
| 被动管理 | 现有随访是被动等待患者上门，无法早期识别高风险情况 |

### 1.2 产品愿景

> **成为每位乳腺癌患者的"副作用预警雷达"——在正确的时间，以正确的方式，传递正确的信息。**

核心价值主张：
- **即时性**: 7x24 小时随时可用，秒级响应
- **专业性**: 基于循证医学指南，融合临床经验规则
- **进化性**: 越用越聪明，持续从真实案例中学习

### 1.3 目标用户

```
┌─────────────────────────────────────────────────────────────┐
│                    目标用户画像                              │
├─────────────────────────────────────────────────────────────┤
│ 主要用户: 正在接受治疗的乳腺癌患者                            │
│   - 年龄: 25-75岁，中位年龄约55岁                            │
│   - 场景: 居家管理、非门诊时间、自主管 理期间                  │
│                                                             │
│ 次要用户: 医疗团队成员                                       │
│   - 接收预警通知、查看患者报告                                │
│   - 提供反馈、调整规则                                        │
└─────────────────────────────────────────────────────────────┘
```

## 二、功能范围

### 2.1 MVP 功能 (v1.0)

#### 2.1.1 评估模块 (Core Loop)

```
用户输入 → AI分析 → 风险判定 → 建议生成 → 结果展示 → 行动触发
```

**输入界面**:
- 文本输入框: "请描述您当前感受到的任何不适或异常"
- 可选: 症状分类卡片（恶心、疲劳、疼痛、皮疹、其他）
- 可选: 持续时间选择（<1天 / 1-3天 / 3-7天 / >7天）
- 可选: 严重程度滑动条（1-10分）

**输出界面**:
| 模块 | 内容 |
|------|------|
| 风险等级 | 🔴 高风险 / 🟡 中风险 / 🟢 低风险 |
| 核心建议 | "立即联系您的医疗团队" / "建议24小时内联系" / "可继续观察" |
| 详细说明 | 风险判定的医学依据（可读性语言） |
| 命中规则 | 哪些规则被触发 |
| 下一步行动 | 具体可执行的建议 |

#### 2.1.2 历史记录模块

- 按时间倒序展示所有评估记录
- 每条记录显示: 时间、风险等级、核心症状摘要
- 点击可展开详情
- 支持按风险等级筛选

#### 2.1.3 团队协作模块

**用户侧**:
- "联系团队"按钮 → 发送通知到医疗团队
- 可附带领当前评估结果的摘要

**医疗团队侧**:
- 接收预警通知（推送/邮件）
- 查看患者评估历史
- 提供反馈标签（准确/不准确/建议调整）

### 2.2 AI 迭代进化模块 (核心差异化)

这是产品的第二增长曲线，使系统从"规则引擎"进化为"智能顾问"。

#### 2.2.1 学习闭环架构

```
┌──────────────────────────────────────────────────────────────────┐
│                        持续学习循环                                │
│                                                                  │
│   ┌─────────┐     ┌─────────────┐     ┌────────────┐           │
│   │ 数据收集 │ ──▶ │ 模式识别与分析 │ ──▶ │ 规则优化    │           │
│   └─────────┘     └─────────────┘     └────────────┘           │
│        ▲                                     │                    │
│        │                                     ▼                    │
│        │                              ┌────────────┐              │
│        └──────────────────────────────│  A/B 测试   │              │
│                                       └────────────┘              │
│                                              │                    │
│                                              ▼                    │
│                                       ┌────────────┐              │
│                                       │ 部署上线    │              │
│                                       └────────────┘              │
└──────────────────────────────────────────────────────────────────┘
```

#### 2.2.2 学习数据来源

| 数据类型 | 描述 | 用途 |
|----------|------|------|
| 隐式反馈 | 用户点击"联系团队"后是否真的去就医 | 验证建议准确性 |
| 显式反馈 | 用户评价"这个建议有帮助/没帮助" | 优化建议质量 |
| 医疗团队反馈 | 医生标记评估结果"准确/需调整" | 专业验证 |
| 行为模式 | 用户重复提交相似症状的频率 | 识别慢性vs急性 |
| 上下文信息 | 治疗阶段(化疗周期)、已知副作用档案 | 个性化判断 |

#### 2.2.3 AI 学习机制

**阶段一: 规则增强 (v1.0-v1.5)**
- 基于专家规则库（来自ref.md的医学知识）
- 从反馈中标记高频误判场景
- 定期人工审核 + 规则更新

**阶段二: 模式学习 (v1.5-v2.0)**
- 聚类分析：识别症状组合模式
- 关联规则挖掘：发现隐藏的危险组合
- 预测模型：预测用户"联系团队"后实际就医概率

**阶段三: 主动预警 (v2.0+)**
- 基于用户历史，预测即将出现的副作用
- 在高风险窗口期主动提醒
- 预防性建议

#### 2.2.4 模型可解释性要求

> ⚠️ **医疗合规要求**: 所有AI判断必须可解释

- 每个风险判定必须关联到具体规则或特征
- 模型更新需要审计日志
- 关键决策（高风险）建议需双重验证机制

## 三、风险评估体系

### 3.1 风险分级定义

| 等级 | 颜色 | 定义 | 响应时间 | 行动 |
|------|------|------|----------|------|
| 🔴 高风险 | Red | 可能危及生命或需要立即医疗干预 | 即时 | 建议立即就医/急诊，触发团队预警 |
| 🟡 中风险 | Yellow | 需要医疗关注，但不紧急 | <24h | 建议联系医疗团队，密切观察 |
| 🟢 低风险 | Green | 可自行管理，需要常规关注 | 常规随访 | 继续观察，记录变化 |

### 3.2 风险规则库 (初始版本)

基于ref.md中的副作用知识构建：

#### 高风险规则 (🔴 立即处理)

| 规则ID | 触发条件 | 建议 | 依据来源 |
|--------|----------|------|----------|
| HR-001 | 呼吸困难、胸痛、胸闷 | 立即拨打120或前往急诊 | IBC症状 |
| HR-002 | 高烧 >38.5°C 持续 | 立即联系团队，考虑急诊 | 感染风险 |
| HR-003 | 严重过敏反应(面部/喉咙肿胀) | 立即就医，可能是过敏性休克前兆 | 药物反应 |
| HR-004 | 腿部疼痛+肿胀（单侧） | 立即就医，排除深静脉血栓 | 化疗并发症 |
| HR-005 | 意识模糊、剧烈头痛、视力变化 | 立即就医，排除脑转移/卒中 | 神经症状 |
| HR-006 | 呕血、黑便、严重腹痛 | 立即就医，消化道出血可能 | 化疗粘膜损伤 |

#### 中风险规则 (🟡 24h内联系)

| 规则ID | 触发条件 | 建议 | 依据来源 |
|--------|----------|------|----------|
| MR-001 | 症状持续 >3天 无好转 | 联系团队评估是否需要调整治疗方案 | 常见不良反应监测 |
| MR-002 | 恶心呕吐影响进食 (>2天) | 联系团队考虑止吐方案调整 | 化疗副作用 |
| MR-003 | 口腔溃疡严重（无法进食） | 联系团队考虑口腔护理方案 | 化疗粘膜炎 |
| MR-004 | 严重腹泻 (>4次/天) | 联系团队，考虑补液和止泻方案 | 靶向/免疫治疗副作用 |
| MR-005 | 皮疹扩散、全身性红斑 | 联系团队评估，可能是药物超敏反应 | 靶向治疗皮疹 |
| MR-006 | 血小板低（发现瘀斑/出血） | 联系团队查血常规，评估出血风险 | 骨髓抑制 |

#### 低风险规则 (🟢 继续观察)

| 规则ID | 触发条件 | 建议 | 依据来源 |
|--------|----------|------|----------|
| LR-001 | 轻微恶心/食欲下降 | 可自行缓解，记录症状变化 | 化疗常见反应 |
| LR-002 | 1-2级疲劳 | 合理休息，适度活动，记录疲劳程度 | 治疗常见副作用 |
| LR-003 | 轻微头痛/肌痛 | 对症处理，持续观察 | 非特异性症状 |
| LR-004 | 局部轻微皮疹（<10%体表面积） | 保持清洁，避免抓挠，观察变化 | 靶向治疗常见 |
| LR-005 | 脱发 | 心理准备，考虑使用冰帽，联系团队讨论 | 化疗副作用 |

### 3.3 症状组合规则

某些单独看是低风险的症状，组合后升级为中/高风险：

| 组合 | 风险升级 | 原因 |
|------|----------|------|
| 发热 + 寒战 | 🟢→🟡→🔴 | 疑似感染（持续高热升级为高风险） |
| 恶心 + 脱水体征(口干/尿深) | 🟢→🟡 | 电解质紊乱风险 |
| 皮疹 + 发热 | 🟢→🟡 | 药物超敏反应 |
| 疲劳 + 呼吸困难(轻微) | 🟢→🟡 | 贫血或心脏毒性 |

### 3.4 治疗阶段上下文

不同治疗阶段的关注重点：

| 治疗阶段 | 高频副作用 | 需要特别关注的症状 |
|----------|-----------|---------------------|
| 化疗后1-7天 | 骨髓抑制、恶心呕吐、粘膜炎 | 发热、感染迹象、出血 |
| 手术恢复期 | 伤口疼痛、淋巴水肿 | 伤口红肿、单侧手臂肿胀 |
| 靶向治疗中 | 皮疹、腹泻、高血压 | 皮疹严重程度、血压监测 |
| 内分泌治疗 | 骨质疏松、关节痛、潮热 | 骨痛、骨折风险 |

### 4.2 核心数据模型

#### 4.2.1 评估记录 (assessment)

```sql
CREATE TABLE assessment (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    -- 用户标识
    user_id UUID NOT NULL,

    -- 输入内容
    raw_input TEXT NOT NULL,           -- 用户原始输入
    structured_input JSONB,             -- 解析后的结构化输入

    -- 评估结果
    risk_level VARCHAR(10) NOT NULL,   -- 'high' | 'medium' | 'low'
    risk_score DECIMAL(5,2),          -- 0-100 风险分数

    -- 决策依据
    triggered_rules JSONB NOT NULL,    -- 触发的规则列表
    reasoning TEXT,                     -- AI生成的推理过程
    evidence JSONB,                     -- 证据详情

    -- 建议
    immediate_action TEXT NOT NULL,     -- 立即行动建议
    follow_up_suggestion TEXT,          -- 后续建议
    team_contact_required BOOLEAN DEFAULT FALSE,

    -- 元数据
    treatment_phase VARCHAR(50),        -- 治疗阶段
    treatment_type VARCHAR(50),         -- 治疗类型
    version VARCHAR(20),                 -- 规则版本

    -- 时间戳
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);
```

#### 4.2.2 用户反馈 (feedback)

```sql
CREATE TABLE feedback (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    assessment_id UUID REFERENCES assessment(id),

    -- 反馈类型
    feedback_type VARCHAR(20),          -- 'user_rating' | 'team_verdict' | 'behavior'

    -- 显式反馈
    is_helpful BOOLEAN,                -- 用户评价
    rating INTEGER,                     -- 1-5分

    -- 隐式反馈
    user_acted BOOLEAN,                -- 用户是否按建议行动
    user_sought_medical_help BOOLEAN,  -- 用户是否就医

    -- 团队反馈
    team_verdict VARCHAR(20),          -- 'accurate' | 'inaccurate' | 'needs_adjustment'
    team_comment TEXT,

    -- 来源
    source VARCHAR(20),                -- 'patient' | 'team'

    created_at TIMESTAMP DEFAULT NOW()
);
```

#### 4.2.3 规则版本 (rule_version)

```sql
CREATE TABLE rule_version (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    version VARCHAR(20) NOT NULL UNIQUE,
    rules JSONB NOT NULL,              -- 规则快照

    -- 变更说明
    change_summary TEXT,
    change_reason TEXT,

    -- 状态
    status VARCHAR(20) DEFAULT 'active', -- 'draft' | 'active' | 'deprecated'

    -- 部署信息
    deployed_at TIMESTAMP,
    deployed_by VARCHAR(100),

    created_at TIMESTAMP DEFAULT NOW()
);
```

```
        ├──[评价帮助?]── 是 ──▶ 记录 is_helpful=true
        │
        └──[评价帮助?]── 否 ──▶ 记录 is_helpful=false
                                  弹出"哪里可以改进?"收集详情

阶段2: 行为追踪
────────────────────────────────────────────────────
用户点击"联系团队"按钮
        │
        └──[?]── 团队确认收到通知? ──▶ 记录 team_notification_opened

用户是否有后续就医记录（需授权）
        │
        └──[?]── 用户提交就医证明 ──▶ 记录 user_sought_medical_help

阶段3: 规则优化
────────────────────────────────────────────────────
每周汇总反馈数据
        │
        ├──[?]── 某规则准确率 < 80%?
        │           │
        │           └── 是 ──▶ 标记为待审核
        │                        进入人工审核流程
        │
        └──[?]── 某症状组合频繁出现但未覆盖?
                    │
                    └── 是 ──▶ 触发规则提案流程
                                 医疗团队审核后加入规则库
```

### 6.3 模型评估指标

| 指标 | 定义 | 目标值 | 监测频率 |
|------|------|--------|----------|
| 规则命中率 | 有反馈的评估中，规则被触发频率 | - | 每周 |
| 用户满意度 | 用户评价"有帮助"的比例 | > 85% | 每周 |
| 团队认可率 | 团队评价"准确"的比例 | > 90% | 每周 |
| 行动一致性 | 用户按建议就医的比例 | - | 每月 |
| 漏报率 | 高风险但被判定为低风险的比率 | < 1% | 每月 |

### 6.4 规则更新流程

```
┌─────────────────────────────────────────────────────────────────┐
│                    规则变更管理流程                              │
└─────────────────────────────────────────────────────────────────┘

提案阶段
    │
    ├── 来源1: AI自动发现（模式识别触发）
    │        └─▶ AI输出候选规则 + 置信度 + 数据支撑
    │
    ├── 来源2: 医疗团队手动提议
    │        └─▶ 提交规则提案 + 临床依据
    │
    └── 来源3: 用户反馈驱动
             └─▶ 反馈聚合分析后生成优化建议

审核阶段 (必须)
    │
    ├── 规则合规性检查（无歧视性、无医疗误导）
    ├── 临床专家审核（高风险规则必须）
    └── 安全审核（边界情况覆盖）

测试阶段
    │
    ├── 离线测试：历史数据回测，验证召回率和精确率
    ├── A/B测试：新旧规则各50%流量，持续1-2周
    └── 监控：新规则的关键指标

部署阶段
    │
    ├── 创建新 rule_version 记录
    ├── 灰度发布（先10% → 50% → 100%）
    └── 持续监控1周

回滚机制
    │
    └── 若指标异常（如误判率上升），自动/手动回滚到上一版本
```

## 七、非功能需求

### 7.1 性能要求

| 指标 | 要求 |
|------|------|
| 评估响应时间 | P95 < 500ms |
| 系统可用性 | 99.9% |
| 并发用户数 | 支持 1000 并发评估请求 |

### 7.2 安全要求

- 所有数据传输使用 HTTPS
- 用户数据加密存储
- 医疗团队访问需要二次验证
- 审计日志完整记录所有操作
- 符合 HIPAA 要求的数据保护

### 7.3 合规要求

- 评估结果必须包含免责声明
- 强调"本系统不替代专业医疗建议"
- 高风险建议必须建议用户联系医疗团队
- 禁止用于诊断，仅用于辅助参考
