## 二、核心架构决策

### 决策 1: Multi-Agent 组织方式

**参考**: Claude Code 的多 Agent 架构

**核心模式**:
- 每个 Agent 是独立的"执行单元"
- Root Agent 通过 Tool 调用激活子 Agent
- Agent 通信通过结构化的 Tool 结果
- 不是通过消息队列，而是通过 Tool 抽象

**最终架构**:

```
┌─────────────────────────────────────────────────────────────┐
│                   Assessment Orchestrator                    │
│                   (Root Agent - 评估编排器)                  │
│                                                              │
│  职责：                                                     │
│  • 接收用户症状描述                                         │
│  • 调用 Symptom Parser Tool → 获取结构化症状                │
│  • 调用 Risk Assessor Tool → 获取风险等级和依据             │
│  • 调用 Advice Generator Tool → 生成建议                    │
│  • 汇总结果，返回给用户                                     │
└──────────────────────────┬────────────────────────────────┘
                             │
        ┌───────────────────┼───────────────────┐
        ▼                   ▼                   ▼
┌───────────────┐    ┌───────────────┐    ┌───────────────┐
│ Symptom      │    │ Risk         │    │ Advice       │
│ Parser Tool  │    │ Assessor Tool│    │ Generator    │
├───────────────┤    ├───────────────┤    ├───────────────┤
│ 职责:        │    │ 职责:        │    │ 职责:        │
│ 解析症状     │    │ 评估风险     │    │ 生成建议     │
│ 标准化术语   │    │ 匹配规则     │    │ 解释决策     │
├───────────────┤    ├───────────────┤    ├───────────────┤
│ 工具:        │    │ 工具:        │    │ 工具:        │
│ • 正则匹配   │    │ • 规则引擎   │    │ • LLM调用    │
│ • RAG检索   │    │ • RAG检索   │    │ • 模板填充   │
│ • NLP解析   │    │ • 上下文     │    │ • 引用标注   │
└───────────────┘    └───────────────┘    └───────────────┘
```

### 决策 2: 规则 + RAG + 大模型混合架构

**核心原则**: 可解释性是关键

```
三层决策机制：

┌─────────────────────────────────────────────────────────────┐
│                   Layer 1: 规则引擎 (确定性)                │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  • 高优先级规则匹配 → 直接返回                               │
│  • 确定性高，无需 LLM                                       │
│                                                              │
│  示例：                                                      │
│  if 包含("呼吸困难") → 高风险                               │
│                                                              │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           │ 如果没有命中规则
                           ▼
┌─────────────────────────────────────────────────────────────┐
│                   Layer 2: RAG 检索 (参考性)                  │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  • 检索相关指南片段                                         │
│  • 提供上下文支持                                           │
│  • 不做最终判断                                              │
│                                                              │
│  示例：                                                      │
│  Query: "恶心呕吐 两天 吃不下"                              │
│  检索: "化疗副作用管理指南 - 恶心呕吐处理"                   │
│                                                              │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│                   Layer 3: LLM 推理 (综合判断)                │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  • 结合规则 + RAG + 上下文                                   │
│  • 生成最终判断                                              │
│  • 必须附带推理过程                                          │
│                                                              │
│  示例：                                                      │
│  综合判断为中风险，建议24小时内联系团队                      │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### 决策 3: 可解释性实现

**每个评估结果必须包含完整的推理链**:

```json
{
  "risk_level": "medium",
  "confidence": 0.87,
  "reasoning": [
    {
      "step": 1,
      "type": "rule_match",
      "description": "症状匹配规则 MR-002",
      "confidence": 0.95,
      "evidence": "用户描述包含'恶心'和'吃不下'"
    },
    {
      "step": 2,
      "type": "rag_retrieval",
      "description": "检索到化疗副作用管理指南",
      "confidence": 0.9,
      "source": "guideline_chemo_2024"
    },
    {
      "step": 3,
      "type": "llm_reasoning",
      "description": "综合判断为中风险",
      "confidence": 0.85,
      "based_on": "规则匹配 + RAG参考 + 持续时间因素"
    }
  ],
  "triggered_rules": ["MR-002"],
  "referenced_sources": ["guideline_chemo_2024"]
}
```

### 决策 4: Agent 八模块优先级

| 模块 | 优先级 | 具体实现 |
|------|--------|----------|
| **规划** | ★★★★★ | Root Agent 使用 ReAct 模式 |
| **记忆** | ★★★★★ | 三层：短期（session）→ 中期（用户历史）→ 长期（医学知识库） |
| **多 Agent** | ★★★★★ | 4 个专业 Agent，通过 Tool 调用协作 |
| Tool/Skill | ★ | 核心：规则引擎、RAG 检索、LLM 调用 |
| 模型 | ★ | Claude API，统一使用 Opus |
| 可解释性 | ★ | 决策链路必须可追溯，每个步骤有 evidence |
| 安全性 | ★ | Cloudflare 安全边界 + 数据加密 |
| 人机交互 | ★ | 混合模式，表单 + 自然语言 |

## 四、Claude Code 风格 Tool 调用模式

```
Root Agent (评估编排器)

┌─────────────────────────────────────────────────────────────────┐
│  messages: [                                                       │
│    {"role": "user", "content": "恶心想吐已经2天了"}              │
│  ]                                                                  │
│                                                                    │
│  tools: [                                                          │
│    {name: "symptom_parser", description: "...", parameters: {...}}│
│    {name: "risk_assessor", description: "...", parameters: {...}} │
│    {name: "advice_generator", description: "...", parameters: {...}}
│  ]                                                                  │
│                                                                    │
│  模型调用 → 返回 tool_use 调用                                     │
└─────────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────────┐
│  tool_use: {                                                       │
│    name: "symptom_parser",                                        │
│    input: {"raw_text": "恶心想吐已经2天了", ...}                 │
│  }                                                                  │
└─────────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────────┐
│  Tool 执行器                                                       │
│  • 内部可以有复杂的推理逻辑                                        │
│  • 内部可以调用其他服务（API、数据库等）                           │
│  • 返回结构化结果                                                  │
└─────────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────────┐
│  tool result: {                                                    │
│    symptoms: [{"name": "恶心呕吐", "confidence": 0.95}],        │
│    rag_sources: ["chemo_guide_v2"]                              │
│  }                                                                  │
└─────────────────────────────────────────────────────────────────┘

循环：继续调用下一个 tool，直到完成
```
